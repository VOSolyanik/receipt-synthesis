A classifier reading a large amount, a merchant and the word «квитанція» in the interface has every reason to call it a payment confirmation; extraction then hunts for fields that are not on the image, and the verdict fails for a reason no log traces back to the TYPE OF INPUT. Formally the class is already covered — `other` routes to `in_review`, which is the correct outcome — but a corpus that contains no such image never measures whether the system arrives there. 🔴 THE MERCHANT DESCRIPTOR IS A SECOND, SEPARATE PHENOMENON, and no document in this repository has ever printed one. The counterparty line is NOT a legal name: it is `*`, the string a payment processor puts into the card network's message. The prefix is a public Ukrainian processor read from `payment_providers` and `aggregators` in config/vendors.json — public marks, used for exactly the trade they are publicly in. The tail is the merchant's name as the descriptor field leaves it: uppercased, truncated, the legal form dropped. So the bank says one string and an invoice for the same purchase says another, and a counterparty cross-check comparing the two fails on a document pair that is entirely genuine. ⚠️ THE NORMALIZATION RULE IS NOT THIS REPOSITORY'S WORK — a consumer decides how to compare them.
